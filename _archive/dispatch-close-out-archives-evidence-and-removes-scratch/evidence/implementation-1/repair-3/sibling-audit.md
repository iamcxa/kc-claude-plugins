# Sibling-site audit in the six designed files

Boundary: scratch.py, dispatch_stage.py, pr_watch.py and their three test files. The bounded searches were calls to record_text/notes_for/claim_root and file writes, gzip/SHA256SUMS/unlink sites. No private repository or adopter content was consulted. This repairs named broken seams in the approved Pilot design; existing dispatch selection, root ownership, compressor and watcher are reused.

## Dispatch selection finding

- dispatch_stage.select_record, existing-record reuse: the owned defect. The old code rendered incoming notes for the old number before deciding whether to reuse it. A path for validation-2 was rejected against validation-1. The regression builds the first native validation, then names validation-2's root, builds it and retries without creating validation-3.
- dispatch_stage.select_record, new-record creation: already validates against newest+1, so it has no old-number mismatch. Repair leaves this validation in force. A prior record that cannot be rendered under the incoming notes is not reused; the selected new record must still validate before any record file is created.
- dispatch_stage.record_text and scratch.notes_for: shared renderer and root boundary, not number selectors. Their root checks remain. The repair does not allow paths outside the selected root, symlinked roots or mismatching ownership.
- dispatch_stage.main, special-role dispatch: uses the same selector and therefore had the same defect. The second engineering-reviewer dispatch regression reproduces it by restoring the old selector, then proves record commit, output and identical retry with the repair.
- dispatch_stage.main, stage scope-notes write: calls notes_for using the already selected path.stem after root claiming; no previous-number comparison. This remains the independent validation before the native builder.
- scratch.dispatch_name/root_for/claim_root: message continuations map to their parent dispatch; namespace/owner identity does not choose a next number. No same selection defect. Existing archive, clone, workflow and owner tests remain.
- pr_watch.newest_for/scratch_lines: read committed records to identify idle cleanup candidates; they do not validate incoming notes or create dispatches. No same defect.
- test_dispatch_stage's direct record_text/input-byte fixtures render a specified number; its retry, changed-checklist, newer-head and failed-build cases use the repaired shared selector. test_scratch's follow-up-root test checks parent mapping, and test_pr_watch's scratch_dispatch/scratch_root are synthetic setup, not production selectors. No independent selector copy remains to repair in these tests.

## Evidence retry finding

- scratch.evidence, compressed-destination validation: the owned defect. Old close compressed/unlinked a.txt before noticing occupied z.txt.gz; after removing the collision, retry named a.txt.gz and hashed the compressed bytes. compression-before.json and compression-red.json retain the reproduction.
- scratch.evidence, existing-gzip decompression and original-digest validation: the same ordering defect. If a later saved gzip is invalid or its original digest mismatches, earlier source files had already changed. Both checks now finish in the read-only planning pass; the regression asserts every file is unchanged on refusal, then repairs the saved gzip and retries.
- scratch.evidence, gzip write/unlink and later manifest write: the same retry metadata defect after a later write error. io-red.json reproduces the wrong a.txt.gz digest after an injected later OSError. The original digest list is now saved after read-only checks and before compression. A completed earlier gzip is recognizable on retry; destination creation uses xb to refuse an occupied destination. io-green.json and the pre-I/O-fix mutation prove this boundary. No source is unlinked until its own gzip write succeeds.
- scratch.evidence, path/type/manifest-input checks: already run before compression. Missing/symlinked paths refuse before deletion; no same mutation-before-check defect. The post-compression retained-size refusal already has the digest list and keeps evidence; its cap/idempotence/restore tests remain.
- scratch.close: calls evidence before removing worktrees/root. Every evidence refusal retains scratch. No separate compressor or digest writer here; the real CLI replay proves collision refusal, retry, owned-root removal and peer survival.
- dispatch_stage's exclusive record create, disposable scope-notes write, and remove_uncommitted: do not compress or delete original evidence. pr_watch's JSON cache uses a temporary file and replacement, and its scratch path is advisory only. No same original-digest bookkeeping defect.
- test_scratch's gzip construction/restoration and corruption cases are fixtures/assertions, not a retained-evidence writer. test_dispatch_stage and test_pr_watch delegate production compression to scratch.py; no compressor copy to repair.

The fixture peer-survival assertion now counts the peer dispatch root, not all /tmp/dev2 worktrees: when TMPDIR is inside the owned root, the synthetic repository's primary worktree is also under /tmp/dev2. The original failure is retained in scratch-green.json; this test-only scope correction follows Captain amendment 2, and product cleanup scope is unchanged. The code does not claim a filesystem transaction or recovery from arbitrary concurrent evidence edits.
