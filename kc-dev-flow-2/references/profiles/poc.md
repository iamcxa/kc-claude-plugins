# POC: bounded proof

Prove one real, demoable journey and its riskiest assumption with the shortest
safe mechanism; the result may be disposable. Use the recorded decision,
credible falsifier, budget and stop point without rewriting them during proof.

Prefer existing code, a library or a CLI over a framework for hypothetical scale.
Integrate before polishing. Test owned logic and the assumption that could
invalidate the experiment; do not duplicate stable dependency tests.
If the recorded limit is exceeded or the user must intervene before
decision-ready, stop product proof and record the changed outcome and limits.
Return to profile selection if the proof creates state that must persist across
sessions or turns, a seam an external system must keep working, beyond-session
operation or retry/recovery duty. Stop extending that work and record
`boundary-crossed:` with `persistent-state`, `external-seam`, `beyond-session`
or `retry-recovery` and one sentence naming the state, seam or duty.

The working route skips ideation. A permanent architecture document, deployment,
PR or specialist consultation is not a default POC requirement; approved
repository rules and actual risk boundaries still apply. Record cleanup and what
the result does not prove. Return the outcome for the next planning decision;
do not create downstream work or preselect its profile.
