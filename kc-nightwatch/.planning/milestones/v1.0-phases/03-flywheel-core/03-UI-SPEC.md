## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, feedback button inner padding, status dot size (8px = 2×xs) |
| sm | 8px | Compact element padding, list item gaps, label-to-field gap |
| md | 16px | Default content padding, dialog section spacing, drawer internal padding |
| lg | 24px | Dialog padding, section separation, wizard step padding |
| xl | 32px | Major layout gaps (not used in current Phase 2 components) |
| 2xl | 48px | Reserved — page-level (bottom nav clearance is 48px) |
| 3xl | 64px | Reserved — phase 4 use |

Exceptions:

| Usage | Value | Reason |
|-------|-------|--------|
| Bottom nav height | 48px (2xl) | Already established in Phase 2 |
| Sidebar width | 240px | Established constraint |
| Chat drawer width | 400px | Locked in CONTEXT.md |
| Dialog max-width | 480px | Established in TriggerDialog |
| Border radius | 6px (inputs, buttons), 8px (dialogs, cards), 4px (badges, small chips) | Established pattern |
| Status dot | 8px × 8px circle | Established pattern |
| BaselineCard + ChatMessage bubble padding | 12px | Existing codebase usage; mid-point between sm (8px) and md (16px); not a general spacing token |

Source: Extracted from existing component inline styles (sidebar.ts, trigger-dialog.ts, target-detail.ts). The 12px bubble/card padding is a codebase-specific measurement, documented as an exception rather than a named scale token to keep the standard set clean.

## Typography

All sizes sourced from existing codebase patterns. Phase 3 does not add new size levels.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Body | 14px | 400 | 1.5 | Default text, run logs, YAML editor (mono face), chat messages, assessment body text |
| Label | 12px | 600 | 1.4 | Section labels, status badges, type chips, tab labels, field labels, feedback buttons |
| Heading | 16px | 400–600 | 1.3 | Dialog titles (h3), target name in detail view |
| Subheading | 18px | 400 | 1.3 | Section headers (h2) — e.g., target name in TargetDetail |

Source: `index.html` global styles + component inline styles. Pattern confirmed: 12/14/16/18px used across Phase 2.

**YAML editor textarea**: `font-family: var(--font-mono); font-size: 14px; line-height: 1.6` — uses Body size (14px). The monospace font face already provides sufficient visual differentiation from prose text; a separate size level is not needed.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0d1117` (`--bg`) | Page background, textarea background |
| Secondary (30%) | `#161b22` (`--panel`) | Sidebar, cards, drawer panel, dialog background |
| Accent (10%) | `#58a6ff` (`--accent`) | See reserved list below |
| Destructive | `#da3633` (`--btn-danger`) / `#f85149` (`--error`) | Remove Target button, rejected feedback state, error status |

Accent (`--accent`) reserved for:
1. Selected sidebar target indicator (border-left + background tint `rgba(88,166,255,0.1)`)
2. Active tab underline in Config page (Targets / Safety tabs)
3. Focus ring on all interactive elements (buttons, inputs, textarea) — `outline: 2px solid var(--accent)`
4. Running status indicator dot on target cards
5. "Edit" unlock button border when in edit mode
6. Links (`<a>` color)

Success (`--success`) reserved for:
1. Thumbs-up button active/selected state (fill background)
2. Completed run status
3. Accepted implicit feedback entry in calibration table

Error (`--error`) reserved for:
1. Thumbs-down button active/selected state (fill background)
2. Failed run status, static YAML parse error banner
3. Rejected implicit feedback entry in calibration table

Warn (`--warn`) reserved for:
1. Config inline warning badges (from self-repair.yaml)
2. Queued/timeout run status

Source: CONTEXT.md locked decisions + existing codebase color usage patterns.

### Interaction Contracts

#### Chat Drawer

- Position: `position: fixed; right: 0; top: 0; bottom: 0; width: 400px; z-index: 200`
- Background: `var(--panel)` with `border-left: 1px solid var(--border)`
- Open transition: `transform: translateX(0)` in 200ms ease-out
- Close transition: `transform: translateX(100%)` in 200ms ease-out
- Backdrop: `rgba(0,0,0,0.3)` — subtle (not modal-dark), click to close
- Header: target name + "NW-Claude" label + X close button + reset button (icon only)
- Message list: scrollable flex column, newest message at bottom
- Input: textarea (1 row, auto-expand to 4 rows max) + Send button aligned right
- User message bubble: `background: var(--chat-user-bg); border-radius: 8px; padding: 8px 12px; margin-left: 48px`
- NW-Claude bubble: `background: var(--chat-nw-bg); border: 1px solid var(--border); border-radius: 8px; padding: 8px 12px; margin-right: 48px`
- Streaming state: trailing `▋` cursor character on last NW-Claude bubble while streaming
- Auto-brief badge: yellow pill "New briefing" shown at drawer toggle button when `brief-ready` event fires and drawer is closed
- Keyboard: Enter = send, Shift+Enter = newline, Escape = close drawer

#### Action Card (run detail)

- Collapsed: signal title + signal type chip + status badge
- Expanded: toggle on click — shows strategy rationale block + reflection block + feedback buttons
- Strategy section header: `font-size: 12px; color: var(--muted); font-weight: 600` — "Strategy"
- Reflection section header: same style — "Reflection"
- Assessment body text: `font-size: 14px; line-height: 1.5; color: var(--text)`
- Feedback buttons: inline after reflection text, right-aligned
- Feedback button sizes: `padding: 3px 8px; font-size: 12px; border-radius: 4px`
- Thumbs-up active: `background: var(--success); color: #fff; border-color: var(--success)`
- Thumbs-down active: `background: var(--error); color: #fff; border-color: var(--error)`
- Disabled (after submit): `opacity: 0.5; cursor: not-allowed` — optimistic on click
- Button labels: "+1" and "-1" (text, not emoji icons, per no-bundler constraint)

#### Baseline Card (top of run detail)

- Always visible, not collapsible — locked in CONTEXT.md
- Position: above action card list, below run header metadata
- Background: `var(--panel); border: 1px solid var(--border); border-radius: 6px; padding: 12px`
- Header label: `font-size: 12px; color: var(--muted); font-weight: 600; margin-bottom: 8px` — "Indicator Baselines"
- Row per indicator: `display: flex; align-items: center; gap: 8px; padding: 4px 0`
- Indicator name: `font-size: 14px; color: var(--text); flex: 1`
- Current value: `font-size: 14px; font-weight: 600; color: var(--text)`
- Trend arrow: ↑ = `color: var(--success)`, ↓ = `color: var(--error)`, → = `color: var(--muted)`
- No border between rows (compact list, border-bottom only if >5 indicators)

#### Config Page (tab layout)

- Tab strip: `display: flex; border-bottom: 1px solid var(--border); margin-bottom: 16px`
- Tab item: `padding: 8px 16px; font-size: 14px; cursor: pointer; border-bottom: 2px solid transparent`
- Active tab: `border-bottom-color: var(--accent); color: var(--text); font-weight: 600`
- Inactive tab: `color: var(--muted)`
- Tab options: "Targets" and "Safety"

#### YAML Editor (per tab)

- Toolbar above textarea: `[Edit]` button (read-only) or `[Validate] [Discard Changes]` (editing)
- Read-only state: textarea `disabled` attribute + `opacity: 0.7; cursor: default`
- Edit mode: textarea fully interactive, `border-color: var(--accent)`
- YAML textarea: `font-family: var(--font-mono); font-size: 14px; line-height: 1.6; width: 100%; min-height: 400px; resize: vertical; background: var(--bg); color: var(--text); border: 1px solid var(--border); border-radius: 6px; padding: 12px`
- Warning badges: amber pill `background: rgba(210,153,34,0.2); color: var(--warn); border: 1px solid var(--warn); border-radius: 4px; font-size: 11px; padding: 2px 6px` — shown inline before the textarea

#### 4-Step Validation Flow (inside config editor, inline — not wizard)

Step indicator: `font-size: 12px; color: var(--muted)` — "Step 1 of 4: Syntax check"
- Step 1 (static parse): instant — show green "Syntax OK" or red error banner inline below textarea
- Step 2 (Haiku): show spinner + "Checking semantics..." + "~$0.01 estimated cost"
- Step 3 (diff): render line diff below textarea — `+` lines `color: var(--success)`, `-` lines `color: var(--error)`, prefix in mono
- Step 4 (confirm): show `[Confirm Save]` button in `var(--btn-primary)` + estimated cost displayed

Error banner: `background: rgba(248,81,73,0.1); border: 1px solid var(--error); border-radius: 6px; padding: 8px 12px; font-size: 14px; color: var(--error); margin-top: 8px`

#### Add Target Wizard (4-step modal)

- Same overlay pattern as TriggerDialog: `position: fixed; inset: 0; background: rgba(0,0,0,0.7); z-index: 100`
- Dialog: `max-width: 520px; width: 90%; background: var(--panel); border: 1px solid var(--border); border-radius: 8px; padding: 24px`
- Step progress bar: 4 dots, filled circles for completed steps, `background: var(--accent)` for current, `background: var(--border)` for future
- Steps: (1) Type selection, (2) North star + goals, (3) Monitors + respond settings, (4) Validation result
- Navigation: `[Back]` secondary button + `[Next]` or `[Validate & Save]` primary button, right-aligned
- Cancel: top-right X, closes without saving

#### Remove Target Confirmation

- Same overlay as TriggerDialog
- Dialog: `max-width: 360px`
- Body: "Remove [target name]? This cannot be undone." in `var(--text)`
- Actions: `[Stay]` secondary + `[Remove]` in `var(--btn-danger)` style (`background: var(--btn-danger); color: #fff`)

#### Dashboard Screen — Primary Focal Point

The active target card in the sidebar is the primary visual anchor of the Dashboard screen. It draws the eye first via the `--accent` left-border highlight and background tint (`rgba(88,166,255,0.1)`), establishing which target's run detail is shown in the main content area.

## Accessibility

- Chat drawer: `role="dialog"` `aria-label="NW-Claude chat"` `aria-modal="false"` (slide-over, not blocking)
- Chat drawer toggle button: `aria-label="Open NW-Claude chat"` — distinguishes toggle from drawer content label
- Chat reset button: `aria-label="Reset conversation"` — icon-only button requires explicit label
- Add Target wizard: `role="dialog"` `aria-modal="true"` `aria-labelledby="wizard-title"`
- Remove confirm dialog: `role="alertdialog"` `aria-modal="true"`
- Feedback buttons: `aria-label="Accept signal"` / `aria-label="Reject signal"` + `aria-pressed` state
- Action card expand toggle: `aria-expanded` attribute
- YAML textarea: `aria-label="[Targets/Safety] configuration"` + `aria-readonly` when locked
- Tab strip: `role="tablist"`, each tab `role="tab"` with `aria-selected`
- Trend arrows: wrapped in `aria-label="trend: up/down/flat"` span (screen readers need text)
- Keyboard: Escape closes all overlays (chat drawer, wizard, confirm dialogs)
- Focus trap: wizard and confirm dialogs trap focus; chat drawer does not (slide-over, not modal)
