**Create app/frontend/lib/use-poll.ts** (~45 lines):
- Import `{ useRef, useEffect }` from `'preact/hooks'`
- Import `{ signal }` from `'@preact/signals'`

**Export a module-level `refreshTrigger` signal** — this is the shared signal that SSE listeners increment to trigger an immediate re-fetch across all usePoll consumers:
```typescript
export const refreshTrigger = signal(0)
```

- Export `function usePoll(fetchFn: () => void, intervalMs: number, shouldPoll: boolean)`
- Inside the hook:
  - `const timerRef = useRef<ReturnType<typeof setInterval> | null>(null)`
  - Store fetchFn in a ref to avoid stale closures:
    ```typescript
    const fnRef = useRef(fetchFn)
    fnRef.current = fetchFn  // always latest
    ```

  - **useEffect for interval polling** — watches `shouldPoll`:
    - If `shouldPoll` and no existing timer: `timerRef.current = setInterval(() => fnRef.current(), intervalMs)`
    - If `!shouldPoll` and timer exists: `clearInterval(timerRef.current); timerRef.current = null`
    - Return cleanup: `if (timerRef.current) clearInterval(timerRef.current)`
    - Deps: `[shouldPoll]` (fnRef handles staleness, intervalMs is constant)

  - **useEffect for refreshTrigger** — watches `refreshTrigger.value`:
    - When `refreshTrigger.value` changes (> 0), call `fnRef.current()` immediately
    - This gives SSE events a way to trigger an immediate fetch outside the polling interval
    - Deps: `[refreshTrigger.value]`

This design implements the CONTEXT.md requirement: "SSE events trigger an immediate re-fetch via a shared @preact/signals signal (e.g., `refreshTrigger`). usePoll watches `refreshTrigger` signal — SSE increment triggers immediate fetch outside the interval."
