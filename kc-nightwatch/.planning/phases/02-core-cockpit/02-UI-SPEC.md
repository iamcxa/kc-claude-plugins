## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline tight spacing |
| sm | 8px | List item padding, button padding vertical, input padding |
| md | 16px | Panel inner padding, form field gaps, sidebar item padding |
| lg | 24px | Section padding, card body, schedule bar height |
| xl | 32px | Layout column gaps, modal padding |
| 2xl | 48px | Major section separators (schedule bar + content area) |
| 3xl | 64px | Page-level vertical breathing room |

Exceptions:
- Sidebar width: 240px (fixed, not spacing-scale)
- Bottom nav height: 48px (touch-friendly minimum, maps to 2xl)
- Log stream line height: 20px (monospace readability, not 8pt grid — acceptable in monospace contexts)
- Phase progress bar height: 8px (visual indicator, not interactive)

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 | 1.5 | Sidebar labels, run list rows, schedule bar text, general prose |
| Label | 12px | 600 | 1.4 | Type badges, status badges, phase labels, section headings, timestamps |
| Heading | 16px | 600 | 1.3 | Target name in sidebar, right panel target title, modal title, page title |
| Mono | 13px | 400 | 1.6 | Log stream output, phase event lines, raw log view |

Font stack (body/heading): `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`
Font stack (mono): `"SF Mono", "Fira Code", "Fira Mono", "Roboto Mono", monospace`

**Typography note — 13px Mono:** The 1px gap between Mono (13px) and Body/Label (14px/12px) is intentional. Mono always renders in its own font stack (`"SF Mono", "Fira Code", monospace`), which has distinct metrics from the system-ui body stack. At 14px, monospace log lines visually crowd the surrounding UI text. 13px compensates for monospace's wider glyph width while keeping log output readable at 1.6 line-height. The font stack boundary is the differentiator, not just the size.

**Source:** Design spec (CSS + no framework), defaults for dark terminal-style dashboards.

## Interaction Contracts

### Master-Detail Layout

- Left sidebar: 240px fixed width, full viewport height, `#161b22` background, `#30363d` right border
- Right panel: fills remaining width, `#161b22` background, scrollable independently
- On first load with no target selected: right panel shows empty state (see Copywriting Contract)
- Target selection is immediate — no loading delay for sidebar switch (data already fetched)
- **Primary focal point:** right panel TargetDetail component — the north star text block is the first element the user's eye should reach when a target is selected. It anchors the entire detail view.

**Source:** CONTEXT.md (master-detail layout decision).

### Schedule Bar

- Full-width, 48px height, `#161b22` background, `#30363d` bottom border
- Layout: `[Scheduler: ON/OFF toggle] [every {N}h] [· Next in {countdown}] [· Last: {status} {time-ago}]`
- Countdown updates every 10 seconds via `setInterval(10_000)` — "1h 23m" granularity is sufficient
- Toggle: clicking ON/OFF calls `PUT /api/schedule` immediately; optimistic UI update
- If worker offline: schedule bar shows "Worker offline" in `#f85149`, toggle disabled

**Source:** CONTEXT.md (schedule bar spec), RESEARCH.md (10s countdown granularity decision).

### Trigger Dialog

- Opens as full-screen overlay (`position: fixed`, `background: rgba(0,0,0,0.7)`) over master-detail
- Modal card: `#161b22` background, `#30363d` border, `border-radius: 8px`, `max-width: 480px`, centered
- Three sections stacked vertically with `md (16px)` gap:
  1. **Mode toggle** — two adjacent buttons "Production" / "Dry-run", only one active at a time, active has `#238636` background
  2. **Custom instructions** — `<textarea>` placeholder "Optional: additional instructions for this run", 4 rows, full width
  3. **Self-repair** — checkbox-style toggle "Run self-repair first" checked by default
- Footer: "Never mind" (ghost) + "Start Run" (primary green) buttons, right-aligned
- Start Run disabled state: `opacity: 0.5`, cursor not-allowed — active when `worker.status === 'online'` AND no run currently in queue/running
- Dismiss by clicking overlay background OR "Never mind" button
- "Run All" reuse: same modal, target label shows "All targets (N targets)" above sections

**Source:** CONTEXT.md (modal dialog decision, 3-section spec, double-trigger prevention).

### SSE Log Stream

- Container: `#0d1117` background (dominant), `border-radius: 4px`, overflow-y auto, max-height fills right panel
- Phase header row: `16px` padding-left, 36px height, `#161b22` background on hover
  - `[timestamp HH:MM:SS]` in `#8b949e` (muted) · `Phase N: Name` in `#c9d1d9` · status symbol right-aligned
  - Status symbols: `●` (spinner animation, `#58a6ff`) running · `✓` (`#3fb950`) complete · `✗` (`#f85149`) failed
  - Click to collapse/expand tool call rows beneath
- Tool call row (indented 32px): `12px` text, `#8b949e` color
  - Agent dispatch: `→ Agent: {name} dispatched`
  - Tool call: `→ Tool: {tool_name}`
- Auto-scroll: enabled by default; pauses when user scrolls up more than 50px from bottom
- Resume button: appears bottom-right as `position: sticky` when auto-scroll paused — "↓ Resume" — `#161b22` background, `#58a6ff` text
- "Show raw" toggle: top-right of log container, switches to `<pre>` with raw log text, preserves scroll position
- Completed run: all phases collapsed by default showing only headers; user can expand

**Source:** CONTEXT.md (SSE log presentation decision, all behavioral specs).

### Run History List

- Filter bar: two filter controls side-by-side — Status dropdown (All/Completed/Failed/With actions) + Target dropdown (All/{target names})
- Run row: status badge (colored) · target name · trigger type (icon: manual/interval/webhook) · duration · action count · time-ago
- Status badge: `completed` = `#3fb950` text on dark bg · `failed` = `#f85149` · `running` = `#58a6ff` with pulse · `queued` = `#d29922` · `cancelled` = `#8b949e`
- Click row → navigates to `#/runs/{id}`
- Live run row: highlighted with `#58a6ff` left border, auto-navigates to live view if only one run in progress

**Source:** CONTEXT.md (run history spec), REQUIREMENTS.md (HIST-01..04).

### Bottom Navigation

- 48px height, `#161b22` background, `#30363d` top border, `position: fixed` bottom
- Three equal-width tabs: Dashboard · Runs · Config
- Active tab: `#58a6ff` text and 2px top border in `#58a6ff`
- Inactive tab: `#8b949e` text
- Config tab in Phase 2: renders stub page (not disabled — navigable but shows placeholder)

**Source:** CONTEXT.md (bottom nav: 3-tab spec), REQUIREMENTS.md (DASH-05).

## Accessibility Baseline

This is a single-user local tool (explicitly out of scope: mobile responsive, multi-user). Minimum accessibility:

- All interactive elements have `:focus` outline in `#58a6ff`
- Color is not the only differentiator for run status — status badge includes text label
- Log stream uses `role="log"` and `aria-live="polite"` for screen reader awareness
- Modal uses `role="dialog"`, `aria-modal="true"`, focus trapped within modal while open
- Buttons have descriptive text (not icon-only)
- Keyboard: Tab navigable, Enter/Space activates buttons, Escape closes modal
