| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-text gap, button icon padding, inline badge padding |
| sm | 8px | Compact element spacing, list-item internal padding, card section gap |
| md | 16px | Default element spacing, card padding, section padding |
| lg | 24px | Section padding, health page inter-section gap |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Bottom nav height (fixed), tall modal headers |
| 3xl | 64px | (reserved — not used in this phase) |

Source: Measured from existing component inline styles across Phases 2–3 — values 4, 8, 10, 12, 16, 24 observed. 10px (sidebar item padding) and 12px (card internal) are legacy values; Phase 4 components use only 8px or 16px for new padding decisions.

- Bottom nav: fixed height 48px (existing, must not change)

- SVG sparkline: 80×20px (from RESEARCH.md Pattern 5)

## Chart Sizing

### Sparkline (per indicator in Health page)
- Canvas: 80px wide × 20px tall
- Stroke width: 1.5px
- Color: `var(--success)` if last > first, `var(--error)` if last < first, `var(--muted)` if equal
- Fallback for <2 data points: render `<span style="color:var(--muted);font-size:11px;">--</span>`
- Source: RESEARCH.md Pattern 5 (pre-populated)

### Reject Rate Line Chart (per indicator)
- Canvas: 240px wide × 80px tall, `overflow:visible`
- Axes: 1px stroke `var(--border)`, x-axis at bottom, y-axis at left
- Y-axis range: 0.0 to 1.0 (reject rate fraction)
- X-axis: run index (1..N, no date labels)
- Chart line: 1.5px stroke `var(--accent)`
- Axis tick labels: 11px, `var(--muted)` (y: "0%", "50%", "100%"; x: first and last run number only)

### Health Summary Bar
- Full width, 40px height
- Background: `var(--panel)`, border: `1px solid var(--border)`, border-radius: 6px
- Text: 14px, centered
- Content: Overall trend label (e.g., "Overall: Improving ↑"), derived from majority of per-target health
- Color: text uses `var(--success)` / `var(--error)` / `var(--muted)` per overall trend

## Health Page Layout

Source: CONTEXT.md `## Health Page Navigation & Layout` decision — pre-populated.

Page route: `#/health`

Layout (top to bottom within page, below global header):
1. **Aggregate health summary bar** — full width, 40px, sticky under schedule bar area
2. **Per-target sections** (one per target, stacked vertically):
   - Target name (16px, weight 600) + health arrow (same `trendArrow()` pattern from `baseline-card.ts`)
   - Indicator row for each indicator: name (14px) | sparkline (80×20px) | current value + unit | trend arrow
3. **Reject rate section** — full width, below all target sections
   - Section label: "Reject Rate by Indicator" (12px, weight 600, `var(--muted)`)
   - One `LineChart` per indicator, displayed in a flex-wrap grid (2 per row on standard viewport)
4. **Acceptance rate** — single line: "Proposals accepted: N / M (X%)" with trend arrow

### Empty State (fewer than 3 runs analyzed)

Render a banner at the top of the health page:

```
Gathering data (N/10 runs) — health metrics are available after 3 completed runs.
```
- Style: `background:var(--panel);border:1px solid var(--accent);border-radius:6px;padding:8px 16px;font-size:14px;color:var(--muted);margin:16px;`
- Sparklines: render with available data (2+ points). Show `--` placeholder for 0–1 points.
- Health arrow: defaults to `→` (stable, `var(--muted)`) when trend is indeterminate.
- Source: RESEARCH.md Pitfall 7 + Open Question 3 (Claude's discretion resolved)

## Interaction Contract

### Health Page Data Loading
- Load strategy: fetch `GET /api/health/:target` for all targets on page mount (parallel `Promise.all`)
- Polling: none — health data is computed from historical runs, not real-time. User refreshes page to update.
- Loading state: render summary bar and target sections immediately with `--` placeholders; replace as data arrives
- Error: show error banner "Could not load health data. Check that the server is running." below summary bar

### Bottom Nav — Health Tab
- Tab order: Dashboard · Runs · Health · Config
- Health tab active state: same pattern as existing tabs — `border-top: 2px solid var(--accent)`, text `var(--accent)`, weight 600
- Inactive: `var(--muted)`, weight 400, transparent top border

### Sidebar Health Arrow
- Fetch timing: `GET /api/health/:target` calls dispatched from Dashboard page mount (same load as sidebar targets)
- Arrow update: re-fetched every time sidebar targets refresh (same poll cycle as runs)
- No arrow shown during loading or on fetch error

### MCP Tool Discovery (no UI surface)
- MCP tools are not exposed in the dashboard UI — they are an API-only feature
- NW-Claude chat tool calls are invisible to the user (tool_use/tool_result loop is server-side)
- Chat drawer UI is unchanged from Phase 3

## Accessibility

- Health arrows use `aria-label` (same pattern as `baseline-card.ts`): `aria-label="trend: up"` / `aria-label="trend: down"` / `aria-label="trend: flat"`
- SVG sparklines: wrapped in `<span role="img" aria-label="{indicator} trend: {direction} ({current} {unit})">`
- All buttons retain `aria-label` and `aria-pressed` where applicable (existing pattern from action-card.ts)
- Focus ring: `outline: 2px solid var(--accent); outline-offset: 2px` (existing global rule — do not override)
- Color is never the sole indicator of meaning: arrows (↑↓→) always accompany color-coded status
