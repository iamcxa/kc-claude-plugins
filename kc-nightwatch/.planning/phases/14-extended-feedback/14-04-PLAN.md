# Plan 14-04: Dashboard Feedback Display for Extended Sources

## Objective

Close the gap identified in 14-VERIFICATION.md Truth #3: "Feedback entries from both Slack and PR review sources appear in the dashboard's feedback view alongside existing dashboard/MCP feedback."

The backend correctly stores feedback from all 5 sources with 3-state verdicts. This plan propagates those types to the frontend and wires the display.

## Context

**Gap root cause:** Phase 14 plans 01-03 built the backend collection pipeline but did not update the frontend to display auto-collected feedback entries. Three files need updates:

1. `api.ts` — `submitFeedback` verdict still typed as 2-state
2. `action-card.ts` — `existingFeedback` prop is 2-state string, not structured data with source
3. `runs.ts` — never calls `getFeedback()` to load existing entries

**Key constraint:** The Preact + HTM frontend uses no JSX — all templates use `html` tagged template literals. No build step.

## must_haves

1. ActionCard displays existing feedback entries including auto-collected ones (slack_reaction, pr_review sources)
2. 3-state verdict (accepted/rejected/uncertain) is visually distinguishable in the UI
3. Per-source labels are shown so users can distinguish manual vs automatic feedback
4. `runs.ts` loads feedback data via `api.getFeedback(runId)` when viewing run detail
