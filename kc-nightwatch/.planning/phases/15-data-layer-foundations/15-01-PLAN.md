**Step 2: Rewrite `getCalibrationData()` in `app/server/services/feedback-store.ts`**

Replace lines 55-94 with the full bucketing + EMA implementation. The function signature stays the same (`async function getCalibrationData(): Promise<CalibrationData[]>`).

Implementation details per D-01 through D-06:

1. Collect all feedback entries (same as current lines 56-63)
2. Skip entries with empty/falsy `run_id` (defensive — log.warn for malformed entries)
3. Build `runTimestamps: Map<string, string>` mapping run_id to earliest submitted_at
4. Sort run_ids chronologically by earliest submitted_at, take last 30 (`slice(-30)`) per D-01
5. Build `runByIndicator: Map<string, Map<string, {total, rejected}>>` — outer key is run_id, inner key is indicator
6. Build `indicatorAllTime: Map<string, {total, rejected}>` for overall stats
7. For each indicator:
   - Compute overall reject_rate = rejected / total
   - If total < 10 (D-04): push CalibrationData with `current_threshold: null`, `threshold_null_reason: "Accumulating data (${total}/10)"`, history from buildHistory()
   - If total >= 10: compute EMA over history array. Start value 0.5, alpha 0.3 (D-05 hardcoded). `emaThreshold = 0.3 * rate + 0.7 * emaThreshold`. Clamp to [0.1, 0.9] (D-06). Push CalibrationData with numeric current_threshold.

Add helper function `buildHistory(sortedRunIds, runByIndicator, indicator): number[]`:
- For each run_id in sorted order, look up indicator counts
- If counts exist and total > 0, push `Math.round((rejected/total) * 100) / 100`
- Skip runs where indicator had no feedback (do NOT push 0)

The exact implementation is provided in the RESEARCH.md Pattern 1 section.
