The first real close of a batch (`sprint: ship-cloud-wrapper`, 2026-09-11) could not run: `close.py`
and `uat-doc.py` (#411) read `<state-dir>/*.md` only, but every merged task had already been moved
to `_archive/` by the pr-merge merge guard, one entity was in folder form (`<slug>/index.md`), and
the scripts assume one `--state-dir` holds both the `docs/dev` entities and ship's
`_ship_fence/`, while the design has two roots (`docs/dev/.spacedock-state` on
`spacedock-state/dev`, `docs/ship/.spacedock-state` on `spacedock-state/ship`). Nothing writes
`<slug>.debrief` into the fence, so `close.py` can never see a debrief as pushed. The batch was
closed by a hand-written receipt validated with `close.py --validate`.

## Accepted outcome

`close.py <sprint> --dev-state <dir> --ship-state <dir>` and `uat-doc.py` with the same two flags
read entities from `<dev-state>/*.md`, `<dev-state>/*/index.md`, `<dev-state>/_archive/*.md` and
`<dev-state>/_archive/*/index.md`, and the fence from `<ship-state>/_ship_fence/<sprint>.json`.
`close.py` records a task's debrief by scanning `<dev-state>/_debriefs/` for the file whose
frontmatter `scope:` or body names the slug, writing `<slug>.debrief -> {status: pushed, path}` into
the fence (or `{status: pending}`), committing the fence path-scoped and pushing by merge, never
rebase. A task dispatched outside `dispatch.sh` (no fence entry) is listed from the entity alone
with `workspace: null`. `--state-dir` remains accepted as a shorthand for both roots being the
same directory.

## Non-goals

* Changing the receipt schema beyond the `debrief` object already defined.
* Writing any debrief on a worker's behalf.
* Any Linear read or write.

## Acceptance criteria

* **AC-1** Against a fixture dev-state with one flat, one folder-form, and one archived entity all carrying the sprint, `uat-doc.py <sprint> --dev-state <d> --ship-state <s>` lists three tasks and exits 0; with `--state-dir` pointing at a dir holding both, the same.
* **AC-2** `close.py <sprint> --dev-state <d> --ship-state <s> --dry-run` prints one `conductor message create` argv per merged task whose debrief is pending and none for a task whose `_debriefs/` file names it; after a non-dry run, the fence carries `<slug>.debrief.status: pushed` with the path for that task.
* **AC-3** `close.py` writes `kc-ship-close-receipt/v2` only when every task is merged with a pushed or failed debrief or `captain_stopped`; the receipt for the real `ship-cloud-wrapper` sprint, regenerated by the script, validates with `close.py --validate` and matches the hand-written one's task set.
* **AC-4** A fixture task with no fence entry appears in the receipt with `workspace: null` and is not counted as a dispatch failure.
