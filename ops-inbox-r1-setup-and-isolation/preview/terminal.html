# Connect a project to its ops inbox (runbook, r1)

<project>        spacedock-dev/subspace-relay
<trigger>        spacedock-dev/subspace-relay-ops-trigger
<inbox>          https://subspace-relay-ops-inbox.netlify.app/inbox  (site subspace-relay-ops-inbox; netlify commands run in the folder S2 linked)
<relay checkout> your local clone of spacedock-dev/subspace-relay, linked to relay's Netlify site
<wrapper>        your secrets wrapper, which puts WEBHOOK_SECRET in the read-back's environment without printing it

Run the steps in order. "Captain only" steps touch an App, a key, a secret, a webhook or a ruleset; nobody else runs them.
Each step names the read-back rows that prove it; S12 runs them all.

## S1 · AGENT MAY RUN · Create the trigger repository
Private, holding only ops-event.yml.

    gh repo create spacedock-dev/subspace-relay-ops-trigger --private --add-readme
    gh api -X PUT repos/spacedock-dev/subspace-relay-ops-trigger/contents/.github/workflows/ops-event.yml -f message="add ops-event" -f content="$(base64 < kc-ops-inbox/trigger/ops-event.yml)"

Read back by: R1 R2

## S2 · AGENT MAY RUN · Create the inbox site and link this folder to it

    netlify sites:create --name subspace-relay-ops-inbox
    netlify link --name subspace-relay-ops-inbox

Read back by: R3

## S3 · CAPTAIN ONLY · Register the dispatch App (in the browser)
Actions write only; install it on <trigger> only. Prints: App ID, installation ID.

    open "https://github.com/settings/apps/new?name=relay-ops-dispatch&public=false&webhook_active=false&url=https://github.com/spacedock-dev/subspace-relay&actions=write"
    on the page: Create GitHub App > Generate a private key > Install App > Only select repositories > spacedock-dev/subspace-relay-ops-trigger > Install

Read back by: R7 R8

## S4 · CAPTAIN ONLY · Register the agent App (in the browser)
Contents and pull requests write; install it on <project> only. Prints: Client ID.

    open "https://github.com/settings/apps/new?name=relay-ops-agent&public=false&webhook_active=false&url=https://github.com/spacedock-dev/subspace-relay&contents=write&pull_requests=write"
    on the page: Create GitHub App > Generate a private key > Install App > Only select repositories > spacedock-dev/subspace-relay > Install

Read back by: R9

## S5 · CAPTAIN ONLY · Store the two App keys
Then delete the two downloaded files.

    netlify env:set DISPATCH_APP_PRIVATE_KEY "$(cat ~/Downloads/relay-ops-dispatch.*.private-key.pem)" --secret
    gh secret set OPS_AGENT_APP_PRIVATE_KEY -R spacedock-dev/subspace-relay-ops-trigger < ~/Downloads/relay-ops-agent.*.private-key.pem

Read back by: R10

## S6 · CAPTAIN ONLY · Create and store the signing secret and the model token
The signing secret goes to the inbox and to relay's deploy previews only.

    V=$(node kc-ops-inbox/bin/secret-new.mjs)
    netlify env:set WEBHOOK_SECRET "$V" --secret
    (cd <relay checkout> && netlify env:set RELAY_OPS_INBOX_SECRET "$V" --secret --context deploy-preview); unset V
    claude setup-token
    gh secret set CLAUDE_CODE_OAUTH_TOKEN -R spacedock-dev/subspace-relay-ops-trigger   # paste the token setup-token printed; gh reads it from standard input

Read back by: R11 R12

## S7 · CAPTAIN ONLY · Store the Slack webhook
Create an incoming webhook for one channel in Slack first. R14, seeing the notice in the channel, is proven in S12.

    read -rs V   # paste the webhook URL; it stays out of shell history
    netlify env:set SLACK_WEBHOOK_URL "$V" --secret; unset V

Read back by: R13

## S8 · AGENT MAY RUN · Deploy the inbox and set its settings
Needs S3's App ID and installation ID and S4's Client ID.

    netlify deploy --prod --site subspace-relay-ops-inbox --dir kc-ops-inbox/site --functions kc-ops-inbox/site/functions
    netlify env:set OPS_TRIGGER_REPO spacedock-dev/subspace-relay-ops-trigger
    netlify env:set OPS_WORKFLOW ops-event.yml
    netlify env:set DISPATCH_APP_ID <S3 App ID>
    netlify env:set DISPATCH_INSTALLATION_ID <S3 installation ID>
    gh variable set OPS_PROJECT_REPO -R spacedock-dev/subspace-relay-ops-trigger --body spacedock-dev/subspace-relay
    gh variable set OPS_AGENT_APP_CLIENT_ID -R spacedock-dev/subspace-relay-ops-trigger --body <S4 Client ID>

Read back by: R4 R5

## S9 · AGENT MAY RUN · Create the state branch and open the setup Draft PR
The PR adds ops-gate.yml and docs/ops/README.md.

    gh api -X POST repos/spacedock-dev/subspace-relay/git/refs -f ref=refs/heads/spacedock-state/ops -f sha=$(node kc-ops-inbox/bin/state-root.mjs --project spacedock-dev/subspace-relay)
    gh pr create -R spacedock-dev/subspace-relay --draft --head ops-inbox-setup --title "chore(ops): connect the ops inbox" --body-file kc-ops-inbox/setup/setup-pr.md

Read back by: R6

## S10 · CAPTAIN ONLY · Apply the five rulesets, one command each
agent-creations: only ops/** and spacedock-state/ops may be created, except by the repository admin role and the release bot listed in the file. The other four have an empty bypass list. Rerun only the line a read-back row names.

    gh api -X POST repos/spacedock-dev/subspace-relay/rulesets --input kc-ops-inbox/setup/ruleset-main.json
    gh api -X POST repos/spacedock-dev/subspace-relay/rulesets --input kc-ops-inbox/setup/ruleset-ops-branches.json
    gh api -X POST repos/spacedock-dev/subspace-relay/rulesets --input kc-ops-inbox/setup/ruleset-state-branch.json
    gh api -X POST repos/spacedock-dev/subspace-relay/rulesets --input kc-ops-inbox/setup/ruleset-agent-creations.json
    gh api -X POST repos/spacedock-dev/subspace-relay-ops-trigger/rulesets --input kc-ops-inbox/setup/ruleset-trigger-main.json

Read back by: R15 R16 R17 R18 R19

## S11 · CAPTAIN ONLY · Merge the setup PR
So ops-gate.yml is on the default branch before any ops PR opens.

    gh pr merge ops-inbox-setup -R spacedock-dev/subspace-relay --squash

Read back by: R20
