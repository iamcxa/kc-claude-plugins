## Decisions

1. **`4p` parked the same day it entered ideation.** Unattended operation is a standing daily
   need, so removing the unattended caller is a feature deletion, not a simplification. Two
   undesigned directions recorded for later: replace `claude -p` with `spacedock claude`, or
   build a small spacedock + ACP harness so an unattended iteration can *ask* at a decision point
   instead of self-approving.
2. **`vf` and `x0` unblocked.** Their premise survived the challenge. Only one coupling remains:
   the event ceiling's provenance depends on which process survives the daemon rework.
3. **`sv` split out of `vf`'s AC-3.** Caller-agnostic — it predates the autonomous path and the
   interactive caller takes the same branch — so it should not wait on an authorization arc whose
   caller shape is still moving.
4. **`sv` is `design: required`, not `trivial-pass`.** It overturns a normative sentence in
   `reference/review-runtime.md`, which is a contract change. The EM gate corrected this.
5. **CI `timeout-minutes` 10 → 20.** Measured, not reflexive: the job ran 9m07s against the
   10-minute cap on main, leaving 53 seconds of margin, and this change was the batch that
   consumed it. The per-assertion cost is the real defect and is tracked as `qh`.

## Observations

1. **A documented guarantee is a falsifiable claim, and this class has now occurred twice.** The
   sentence written into the protocol document — "leaves exactly one path to the POST" — landed
   with its code, passed CI, and passed EM review while being false; one crafted input walked a
   second path and posted. Slice 1's P1 was the same class. The doc-diff rule only checked that
   behaviour and doc landed *together*, which is presence, not truth.
2. **An assertion that holds in both worlds is decoration.** A symmetry assertion compared two
   commands to each other; both said `posted` before the fix and `ambiguous` after. It surfaced
   only because the RED count came in three lower than the number of assertions written.
3. **Local being 6-7x slower than CI was not the tests getting heavier.** 50 `python3` launches
   took 28.3s wall at 0% CPU — the process is blocked on exec interception, not computing. Read
   the CPU accounting, not the clock.
4. **"Shall I continue?" at a non-gate point is not caution.** It hands the steering wheel back,
   costs a turn to say yes, and trains the captain to rubber-stamp — which is what makes the real
   gates cheap to wave through. `#64`'s `Gate Authority` names this failure mode and is now on
   main; the fix is that silence is not a gate.
5. **Every reviewer round this session earned its keep, and each was wrong about something.** The
   EM caught a false premise in the entity; the cross-vendor pass killed an unmeasurable AC but
   mis-framed a stranding risk on a command that takes no gate; the silent-failure lens found a
   real ordering hazard but rated a pre-existing gap as newly introduced. Adjudicating each
   against the code — not the report — is what separated the three.
