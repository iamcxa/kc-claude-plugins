# Treatment child-custody remediation proposal

## Decision

Replace the candidate's direct subprocess implementation, without adding a wrapper or a new source file, with a custody-backed per-attempt runner in `kc-pr-flow/scripts/review-capability.py`. Preserve the existing `--prepare-only`, `--collect-dir`, request/result validation, retry, and finalization contracts. Replace the six direct-dispatch tests in `kc-pr-flow/scripts/review-capability.test.py` with success, nonzero-exit, timeout/descendant, environment, startup-surface, and artifact-tamper tests. These are the only two proposed product files.

This is a proposal, not a fix. It does not authorize an implementation, a provider call, or a continuation of the stopped comparison.

## Evidence boundary

The no-model probe used the pinned treatment source at `0d2e3164ccd2d60006688c5443717b818825a305`, a local executable stub named `claude`, and disposable Git fixtures. The full CLI path was exercised for six successful and six nonzero attempts; `dispatch()` was also exercised at its real timeout boundary with a child that launched a TERM-ignoring descendant. The sanitized results are in `evidence.json`.

Demonstrated current behavior is narrower than the earlier risk statement:

- `review-capability.py:968-979` copies every parent environment entry except four Git-token names. A controlled unrelated sentinel reached every stub child, while all four excluded test token names did not. This demonstrates broad propagation; it does not demonstrate that a real credential leaked in the stopped treatment.
- `review-capability.py:981-997` gives each child pipe-backed stdin/stdout/stderr, and discards the returned stderr. The stub emitted stderr in all success, failure, and timeout cases; no provider-stderr artifact was retained. Attempt and audit records retained neither exit code nor terminal reason.
- On timeout, the stub emitted 23 stdout bytes, but the retained provider raw file was empty. The existing `killpg`/`wait` cleanup did terminate both the child and its TERM-ignoring descendant. Thus cleanup is already effective in this fixture; partial terminal evidence is not.
- The actual child argv requests the model/effort, JSON output, empty tools, strict empty MCP, schema, prompt, and per-attempt budget (`review-capability.py:2074-2100`). It does not request restricted or safe mode, empty setting sources, an explicit settings object, hook events, or a debug file. No plugin flag is passed, but flag absence is not proof of the effective plugin surface.

Missing or unknown evidence must not be restated as observed harm. No adapter child ran in the stopped treatment, so there is no observed adapter credential disclosure, hook/plugin load, fallback, marketplace action, remote side effect, provider receipt, or treatment cost. The current one-object JSON output has no initialization event, so effective model/tools/MCP/plugins are not proven and effective settings/hooks are unknown. The local probe also does not establish compatibility of a remediated argv, auth mode, stream parser, or managed-policy behavior on a real host.

Existing interfaces already cover important pieces and should be reused: `store()` creates exclusive mode-0600 artifacts (`review-capability.py:335-340`); the mechanical-test runner captures both streams and kills a process group (`:628-680`); `host_files()` freezes bounded requests and a result schema (`:1844-1873`); `host_progress()` and `collect_host()` serialize assignment, validate directory/config/identity, retain raw responses, and enforce retry order (`:1876-1956`). The missing unit is child custody, not another review protocol.

## Smallest integrated source change

Keep the current top-level behavior but make each direct attempt use the same frozen request and collection semantics as the host route:

1. During preparation, create an attempt directory with mode 0700 and exclusive mode-0600 prompt, explicit empty settings, and system-prompt files. Bind their bytes and the existing result-schema file by SHA-256 in an immutable attempt manifest. A run may consume only a pending `{capability, attempt}` from `host-progress.json`; paths, identity, plan/config hashes, and HEAD must still match.
2. Build child argv solely in source. For the current Cloud environment, require the pinned executable/model/effort in normal auth mode and include `--restricted`, `--safe-mode`, `--setting-sources ''`, `--settings <frozen-empty-settings>`, `--output-format stream-json`, `--verbose`, `--include-hook-events`, `--debug-file <unique-private-path>`, `--tools ''`, `--strict-mcp-config`, the empty MCP object, frozen schema bytes, system-prompt file, and the divided attempt budget. Pass no `--plugin-dir`, agent, or skill input. Also require init to report empty tools, MCP servers, plugins, and skills. Do not accept an opaque caller command. The registered Cloud model-free check established normal provisioned OAuth as logged in and `--bare` as `loggedIn=false`; therefore `--bare` is inapplicable here. It is only an alternative for a separately pinned future environment that first proves non-keychain authentication without a model.
3. Construct the non-auth child environment from an explicit, preregistered key-name allowlist rather than a denylist, while preserving in-place access to the already provisioned Cloud OAuth source. Add a repeatable key-name/file input at the CLI boundary, validate names, fail before spawn if a required key is missing, and resolve values only in memory. Do not create a fresh HOME/config tree and do not copy, relocate, read, or serialize credentials. Pass through only the exact host handles and environment keys required by the model-free normal-mode auth check; the durable receipt records only `provisioned_first_party_oauth` and boolean login status, never credential paths or values. For non-auth state, record key names and allowlisted nonsecret controls only. Set `DISABLE_AUTOUPDATER=1`, remove `FORCE_AUTOUPDATE_PLUGINS`, and set `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` plus `CLAUDE_CODE_DISABLE_OFFICIAL_MARKETPLACE_AUTOINSTALL=1` on every child; retain these nonsecret values in the configured receipt.
4. Preopen exclusive mode-0600 stdout and stderr files, pass the prompt through a regular read-only file descriptor, and give the CLI a unique debug path inside the private attempt directory. After every terminal path, fsync and hash the three durable outputs. Never reconstruct stdout/stderr from exception attributes.
5. Start a new session/process group. On timeout or cancellation, send TERM to the group, wait for a short fixed grace period, send KILL to the group if needed, reap the direct child, and only then seal the receipt. Spawn error, normal exit, nonzero exit, signal, timeout, and supervisor cancellation must each produce exactly one exclusive terminal receipt containing timestamps, return code/signal, normalized terminal reason, controlled argv, environment key names, artifact byte counts/hashes, and cleanup outcome.
6. Parse the retained stream after reaping. Require exactly one initialization event before exactly one final result. The receipt has two separate sections: `configured` records the controlled argv, frozen settings hash/content class and nonsecret traffic controls; `observed` records the init model plus tool, MCP, plugin and skill lists and the hook-event count. Require the init model to equal the request, all four lists to be empty, and the hook-event count to be zero. The configured section proves only what was requested; it does not prove that settings took effect. The observed section proves only behavior exposed by init/hook events. Any effective settings or managed-policy surface the pinned CLI does not expose remains unknown and is a STOP, not an inferred pass.
7. Extract the structured capability result from the retained final event and pass it through existing `validate_result()`/`collect_host()` behavior. Preserve the complete stream separately. A success requires exit zero, valid startup, one valid result, and a complete terminal receipt; all other paths become the existing transient/terminal/unavailable outcomes without losing evidence. Keep per-attempt cost/usage only from its one final event so reconciliation cannot double-count it.

The runner may retain the current bounded parallel scheduling, but assignment and artifact creation occur before spawn and each lane owns disjoint filenames. No later lane may launch after the first observed STOP-class custody violation. The next candidate is immutable: any source, settings, allowlist, executable, prompt, or planner change invalidates preflight and requires a new candidate ID and approval.

## Sequencing correction

FO must not acquire an admission/treatment launch claim while a required technical preflight is pending. Before any future launch, an independent model-free preflight receipt must be complete, committed, pushed, and explicitly marked PASS against the immutable candidate. It must bind candidate and denominator commits; source audit; executable path/version/hash; argv-template, settings, system-prompt, env-key-list, source/plugin/toolkit/target and planner hashes; and success/nonzero/timeout/tamper test results. Only after FO reads that durable PASS may it create the exclusive launch claim. A missing, stale, or contradictory receipt is a STOP. The earlier launch-before-reply sequence is an operator/FO sequencing defect; it is not evidence that candidate review behavior is unsafe.

## Implementation and validation split

Implementation is limited to the two source files above and must not touch schemas, catalog, runtime shell, workflow, documentation, or add a launcher. It replaces the direct dispatch function and its direct branch while keeping prepare/collect/finalize externally stable.

Model-free implementation checks must fail against the current source and pass only after the change:

- Inject one unrelated sentinel and four excluded token fixtures; assert the sentinel is absent from the child, required allowlisted names arrive, provisioned auth remains in place without copying, and receipts contain only auth mode/status plus non-auth names/nonsecret controls.
- Emit stdout and stderr, then exit 0 and nonzero; assert byte-exact durable files, exit/terminal metadata, one sealed receipt, and no overwrite on replay.
- Emit partial output, spawn a TERM-ignoring descendant, and exceed timeout; assert partial bytes survive, TERM/KILL/reap disposition is recorded, no descendant remains, and no later lane starts.
- Make stdout/stderr/debug/manifest paths symlinks or pre-existing files; assert failure before provider spawn.
- Emit missing/duplicate/out-of-order init/result events, a wrong model, nonempty tool/MCP/plugin/skill fields, or a hook event; assert terminal failure. Assert configured and observed receipt sections cannot substitute for each other. Emit a valid stream and assert normal collection and exactly-once cost/usage extraction.
- Mutate HEAD, settings, prompt, env-key list, host progress, or request after preparation; assert failure before spawn. Remove an allowed auth key and assert the same.

Integration validation, under separate authority, must then run the exact installed binary with the same subcommand-first, normal-mode, model-free auth/status check and a local no-network stub before any provider call. It must report only auth mode and login status, not credential paths or values. A real one-call compatibility check is not authorized here and, if later authorized, must have its own claim, budget, deadline, durable streams, and stop-on-first-failure rule. STOP on any unretained terminal stream, unverifiable observable surface, configured/observed evidence conflation, unexpected mutation/network process, surviving descendant, duplicate receipt, missing cost, source-count excess, or mismatch to preregistration.
