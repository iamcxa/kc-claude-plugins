0.85.0
conductor - manage cloud workspaces and coding agents

Usage: conductor <command> [args] [options]

Authentication:
  conductor auth login [--token <token>]
      Save an API token to the macOS Keychain
  conductor auth logout               Remove the saved API token from the keychain
  conductor auth whoami               Show the configured token + base URL and verify against the API
  conductor auth status               Print whether a keychain entry exists (does not print it)

Project:
  conductor project list [--limit <n>] [--offset <n>]
      List all projects you have access to
  conductor project get <projectId>   Show a project
  conductor project workspace <projectId> [--limit <n>] [--offset <n>] [--channel <channel>]
      List workspaces under a project

Workspace:
  conductor workspace list [--creator <userId>] [--mine] [--since <date>] [--state <state>] [--repo <repository>] [--name <substring>] [--include-archived] [--limit <n>] [--offset <n>] [--channel <channel>]
      List workspaces across your organization
  conductor workspace create [--project-id <id>] [--repo-url <url>] [--branch <name>] [--name <name>] [--session-name <name>] [--agent <agent>] [--model <model>] [--effort <level>] [--fast-mode] [--message <text>] [--message-file <path>] [--env <key=value>] [--channel <channel>]
      Create a workspace (and first session)
  conductor workspace get [workspaceId] [--channel <channel>]
      Show a workspace
  conductor workspace rename [workspaceId] --name <name> [--channel <channel>]
      Rename a workspace
  conductor workspace archive [workspaceId]
      Archive a workspace
  conductor workspace session [workspaceId] [--include-archived] [--limit <n>] [--offset <n>] [--channel <channel>]
      List sessions under a workspace
  conductor workspace status [workspaceId]
      Poll workspace lifecycle status

Session:
  conductor session create [--workspace <workspaceId>] --agent <agent> [--session-id <id>] [--name <name>] [--model <model>] [--effort <level>] [--fast-mode] [--message-id <id>] [--message <text>] [--message-file <path>] [--channel <channel>]
      Start a new session in a workspace
  conductor session get <sessionId> [--channel <channel>]
      Show a session
  conductor session rename <sessionId> --name <name> [--channel <channel>]
      Rename a session
  conductor session archive <sessionId>
      Archive a session (close its chat)
  conductor session message <sessionId> [--after <messageId>] [--limit <n>] [--offset <n>]
      List a session's transcript messages
  conductor session status <sessionId>
      Get the status of a session
  conductor session cancel <sessionId>
      Cancel a running session

Message:
  conductor message create --session <sessionId> [--message <text>] [--message-file <path>] [--message-id <id>] [--channel <channel>]
      Send a user message in a session
  conductor message get <messageId>   Look up a message by id

Other commands:
  conductor model                     List each agent's model ids, effort levels, and defaults
  conductor sql <query>               Run a read-only SQL query over session_transcripts_view
  conductor help [command]            Show help for a command

Global options:
  -v, --version                       Show version number
  --json                              Output JSON instead of human-readable tables (auth commands excepted)
  --token <token>                     Use this token (overrides env + keychain)
  --debug                             Log every HTTP request and response to stderr
  --no-color                          Disable ANSI colors
  -h, --help                          Show help for command

Usage tips:
  - Add --json for machine-readable output (auth commands are human-readable only).
  - Use deep links instead of IDs to direct users to work you've started; deep links are clickable, while IDs are not.
  - Use `session create` when the new agent could share an existing workspace's files and branch; use `workspace create` when the work needs an isolated environment and branch.
  - Prefer internal subagents for read-only tasks; creating Conductor workspaces or sessions for them is fine when the user asks for it (e.g. a specific agent or model only available through Conductor).
  - List commands are paginated with a small default page size; pass --limit (up to 100) and step --offset while the --json response reports hasMore, rather than assuming the first page is everything.
  - Poll a session with `conductor session message <sessionId> --after <lastMessageId>` instead of re-listing with --offset.
  - Use `workspace list --mine` for your workspaces, and add `--since <ISO date>` for recent activity.
  - When a user asks about "my" PRs, workspaces, or sessions, scope to the caller: use `workspace list --mine`, or run `conductor auth whoami` and filter `WHERE workspace_creator_id = '<userId>'` in `conductor sql`; never answer a possessive question from an unfiltered organization-wide listing.
  - To find sessions by transcript content, use `conductor sql`; batch many session lookups into one `WHERE session_id IN (...)` query instead of issuing one query per session. `conductor sql --help` documents the queryable view and rate limit.
  - Conductor supports agents and models from multiple providers; before assuming a model is unavailable, check `conductor model` for each agent's model ids, effort levels, and defaults, and use the corresponding agent.
  - Run `conductor <command> --help` for details on any single command.

Examples:

Start a new session in the same workspace:

  conductor session create \
    --agent codex \
    --model gpt-5.6-sol \
    --name "Reviewer" \
    --message "Review these changes. Make a case that we shouldn't merge them."

  conductor session create \
    --agent claude \
    --model sonnet-5-1m \
    --name "Implementer" \
    --message "Implement these changes: [...]"

  conductor session create \
    --agent claude \
    --model opus-5-1m \
    --name "Explore strategy X" \
    --message "Explore strategy X: [...]"

Start a new workspace (for example, to kick off work on a very large or unrelated project):

  conductor workspace create \
    --project-id <projectId> \
    --agent codex \
    --model gpt-5.6-sol \
    --name "Investigate transient error" \
    --message "I noticed an error while working on ... I was able to get around it by ... Do a more thorough investigation."

  conductor workspace create \
    --project-id <projectId> \
    --agent claude \
    --model opus-5-1m \
    --name "UI code quality" \
    --message "We had ... problems in implementing ... How can we improve the quality of our UI code to prevent these problems?"

Send a message to a session:

  conductor message create \
    --session <sessionId> \
    --message "Make these adjustments: ..."

Wait for a session to complete:

  while true; do
    status=$(
      conductor --json session status "<sessionId>" |
        jq -r '.status'
    )

    if [ "$status" = "idle" ]; then
      echo "Session complete"
      break
    fi

    sleep 2
  done

Exit codes: 0 success, 1 runtime error, 2 usage error, 3 auth error, 4 server error.
