## Issues — Spacedock

- **Previous debrief's `last-commit: 9297802` was a local-only SHA**. When PR #8 merged via rebase, origin/main got rebased SHAs (e.g., `e139f53`, `9ee4f7c`, etc.) and the local-only `9297802` doesn't appear on origin's history. Today's debrief `git log 9297802..HEAD` returns content polluted with origin/main commits already covered by the previous session's debrief. The skill's boundary algorithm assumes the previous `last-commit` is a stable ancestor of HEAD; that assumption breaks under squash/rebase merges that rewrite SHAs.
  - **Suggested fix**: debrief skill should record TWO boundary fields — `last-commit-local` (what was tipped on local at debrief time) AND `last-commit-on-merge-target` (resolved post-merge to the actual stable SHA on the merge target). Or simpler: record `boundary-prefer: <slug-or-content-anchor>` so the next debrief can re-resolve the boundary from content even when SHAs were rewritten by squash/rebase.
  - Not file-as-issue worthy unless this pattern repeats; one-off bootstrap artifact this session.
